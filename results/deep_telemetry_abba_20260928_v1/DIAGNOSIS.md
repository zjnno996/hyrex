# 本轮结论

正式实验完成 160 请求：原生、深 KV、深 KV、原生，各 4 sessions × 10 轮。每次启动 10 个无关 warmup，随后逐请求清理 GPU prefix cache、保留 CPU cache。原生源码未修改；CPU affinity 统一为节点 0 的 CPU，未强制内存绑定。两边 prefill budget 仍分别为 528、2048，因此不是严格单因素实验。

|执行批次|续轮平均 TTFT ms|
|---|---:|
|原生 1|160.539|
|深 KV 1|164.061|
|深 KV 2|161.605|
|原生 2|160.520|

合并续轮平均：原生 160.530 ms，深 KV 162.833 ms，深 KV 慢 2.303 ms / 1.43%。两遍原生均值相差 0.020 ms，深 KV 相差 2.455 ms。仅两个批次/方案，不构成统计显著性证明。本轮未观察到平均 TTFT 加速，不能泛化为所有工作负载都无收益。

每续轮平均多复用 267.56 个位置的 K/V 投影，完整模型 forward token 数没有减少。深 KV 的 forward 数已核对本轮日志，原生由 prompt 减共同命中长度推算。逐轮和逐 session 明细见 RESULTS.md、per_session_turn.csv。

## GPU / PCIe 观测

四批正式请求窗口内共 189 个 NVML 样本：均为 Gen4 x16；GPU 核心频率 2520–2730 MHz；各批均值约 2528–2538 MHz；采样最高温度 43℃。不支持持续低 PCIe 链路速率或持续低核心频率的解释，但采样可能遗漏短暂变化。

100-ms 采样是设备级瞬时吞吐观测，不能积分当成精确逐请求字节数，也不能由峰值比较有效 H2D 带宽。按命中长度推算的 Full KV 有效载荷：原生 28.42 MiB、深 KV 36.78 MiB（额外 8.36 MiB）；不包含 SSM、填充、元数据及 D2H。

## 恢复实现与计时口径

日志中每续轮主机侧 retrieve 处理耗时：原生两遍 3.583 / 3.222 ms，深 KV 9.611 / 9.528 ms。平均 3.403 / 9.569 ms。函数记录完成事件后返回，没有在这里同步等待全部 GPU 拷贝完成，不能把这些数当成 PCIe 时间或直接从 TTFT 中相减。

原生的 execute_object_group_transfer C++ 批量提交入口已确认可用。当前深 KV 的 Full16 分支先进入 _transfer_batched_full_pages 并返回，绕过原生的 _run_object_group_transfer_plan；仍包含 Python 批次/内存连续性遍历和多个复制提交。它是值得做受控消融的实现差异，不是已证明独自导致全部 2.303 ms 差距。

## 环境限制与未完成项

- numa_snapshots.json 记录最大匿名内存映射：首遍原生跨节点且多数页在节点 1；另外三遍采到的大映射均在节点 0。没有与 allocator 指针对应，不能确证全部就是 cache pool，也不能由相关性推断耗时因果。
- 隔离子进程尝试 set_mempolicy(MPOL_BIND,node0) 返回 EPERM；不能宣称消除了 NUMA 干扰。
- 额外 GPU 分项 profile 未取得：诊断服务在第一块模型权重加载时持续 D 状态，等待 blk_mq_get_tag，系统 I/O PSI full avg10 约 73%。已中止诊断并触发清理；没有运行任何诊断请求，不影响已完成正式 TTFT 数据的计时。
- 因此本轮不能给出最终版本的投影耗时、纯 H2D 时间或精确 TTFT 分解。profile_status.json 明确记录这一点。

下一步优先保持独立索引不变，将 Full16 物理传输接入原生批量提交方式，做同路径对照；并在环境稳定时补相同请求的 GPU profile。不要先假定它必然带来正收益。
